# M6 Phase C corpus closeout

Date: 2026-08-10

Status: complete. This report closes the corpus item in the Phase C backlog.

## What was measured

The evaluator is read-only. It scans JavaScript and TypeScript source, calls the
same `proposeStaticConversion` entry point used by the mechanical lane, and
records a proposal only after compiler, lint, binding-integrity, and independent
CSS comparison evidence pass for the generated bytes.

The report uses counts and refusal histograms. It does not turn a conversion
percentage into a safety claim. No target repository files were written, and no
target repository test suite was represented as having run.

Three populations were used:

| Population                | Revision                                   | Purpose                                                           |
| ------------------------- | ------------------------------------------ | ----------------------------------------------------------------- |
| Phase C capability corpus | `eb4afcb1`                                 | Keep every approved comparison model live.                        |
| `react-select`            | `4b6948078684bee394e09dd8e7cdc2d7f89e0fad` | Compact real Emotion object-style and classic-runtime population. |
| Sentry `static/app`       | `ac2f5339cace71f72962997f8e8358f3cef1d9b8` | Large mixed application and architecture-boundary population.     |

The real-repository runs used the evaluator at `f64a176c`. Standard generated,
dependency, build, coverage, and vendor directories were excluded. Declaration
files were excluded.

### Sentry

- Source files scanned: 8,127.
- Files mentioning Emotion: 1,769.
- Files recognized by the source-only Emotion adapter: 0.
- Crashes: 0.

This is not evidence that Sentry has no relevant sites. It is evidence of a
current integration boundary:

- Sentry declares `jsxImportSource: "@emotion/react"` in `tsconfig.json`.
- No scanned file had an exact local Emotion JSX pragma.
- 1,533 files mention `@emotion/styled` and 1,533 contain a `styled(...)` call.
- 619 files mention `@emotion/react`.
- 44 files contain a JSX `css=` spelling.

Those counts overlap and are syntax indicators, not eligible-site counts. The
inventory analyzer can already produce a `known` project-activation fact from
the config, but the file proposer intentionally accepts no unbound activation
boolean. Feeding project activation into conversion requires the fact and its
config inputs to be included in the snapshot, candidate, evidence, and stale
check. That integration belongs at the M7 fact/capsule boundary. Most of the
Sentry population is `styled`, which remains contextual work.

## Conclusions

1. Every approved Phase C model is exercised by a permanent gated corpus.
2. The real repository pass found no crashes and no proposal that bypassed its
   evidence gates.
3. Corpus evaluation found and removed one coverage-only emitter bug without
   weakening the lint boundary.
4. The largest observed coverage constraint is architectural routing, not a
   missing selector model: project activation facts do not yet flow into the
   deterministic proposer, and `styled` is outside the mechanical lane.
5. Within react-select's recognized source population, JSX spread/merge cases
   dominate refusals. They require contextual contract reasoning and should not
   be admitted merely because they are frequent.
6. Among deterministic extensions observed here, additional shorthand families
   are the first evidence-backed candidate. The corpus does not justify moving
   them ahead of M7.

## Ordered follow-up

1. In M7, bind `known` project-activation facts and their input hashes through
   capsule, candidate, evidence, and stale validation before allowing the
   deterministic proposer to use repository configuration.
2. Build the vendor-neutral contextual protocol and skill so `styled`, JSX
   spreads, custom components, and dynamic values receive explicit tasks rather
   than disappearing into an `unchanged` count.
3. In M8, retain Playwright/repository render providers as optional evidence for
   contextual candidates; absence remains a prominent limitation, not pass.
4. If later repository evidence supports another deterministic model, evaluate
   additional shorthand families first, then use fresh histograms to reorder the
   remaining mechanical backlog.
